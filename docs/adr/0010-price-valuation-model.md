# 0010 — The price valuation model: target, validation, explanations and interval

**Status:** Accepted
**Date:** 2026-09-14

## Context

The product's central claim is that it can tell a buyer whether a listing is fairly priced. That
requires a model, and a model requires four decisions that are easy to get wrong in ways nobody
notices: what it predicts, how it is judged, how it explains itself, and how certain it says it is.

Two constraints shape all four. The dataset is a few hundred synthetic listings generated by the
seed, not a market sample. And the thesis is judged on whether the evaluation is honest, not on
whether the number is small.

## Decision

### 1. Predict the log of price per square metre

Floor area explains most of a total price by itself. A model predicting the total can score well
while knowing nothing else, and its R² would flatter it. Dividing area out leaves the part of the
price the remaining features have to earn.

The log follows from the market being multiplicative. A renovation adds a percentage to a flat's
value rather than a fixed number of dram, and the seed's own price model is a product of
multipliers for exactly that reason. Logging turns those into additive effects, which is what a
squared-error objective assumes and what makes an additive SHAP decomposition mean anything.

Everything is converted back to dram before it is scored, so every published figure is an error
in the unit a buyer sees.

### 2. Report two validation schemes, not one

Random k-fold answers "how well does it price a flat in a district it knows". Leave-one-district-out
answers "does anything it learned transfer to a district it has never seen". Both are reported,
always, because the gap between them is the measure of how much of the model's accuracy is
neighbourhood memory rather than understanding. On the seeded data the mean absolute percentage
error roughly doubles when a district is held out.

Both schemes refit the model **and** the baseline inside every fold. The baseline is the one the
brief asks for, a linear regression on floor area alone, and it exists so that a gradient-boosted
ensemble has to prove it is worth its complexity.

### 3. Explanations are exact TreeSHAP, from LightGBM itself

LightGBM's `pred_contrib` implements the TreeSHAP algorithm exactly, so the `shap` package is a
training dependency for global plots rather than a runtime one. That keeps a large scientific
stack out of the served image and changes none of the numbers.

Because the target is logged, a contribution is a log multiplier; exponentiating it yields the
"+12%" form the interface shows. A test asserts that the contributions and the base value
reconstruct the prediction, so an explanation can never become a plausible story detached from
the number it claims to explain.

### 4. The interval is quantile regression, then conformalised

Two further boosters at the 10th and 90th percentiles give a range that widens where the model
is less certain. On this dataset the raw range keeps nothing like its promise: it covers around
60% of asking prices out of fold, not 80%.

Rather than publish a range that is wrong, the training run measures a single multiplicative
widening factor on out-of-fold predictions, in the manner of conformalised quantile regression
(Romano, Patterson and Candès, 2019), and stores it with the model. This matters beyond
tidiness, because the "fair price" badge calls a listing mispriced exactly when its asking price
falls outside this range, and an interval that is too narrow would label ordinary listings as
bargains and traps.

### 5. A model is an artefact with a description, and it is committed

Three boosters in LightGBM's text format plus `metadata.json`. Text, not pickle: a pickle is tied
to the library version that wrote it and executes code on load. The metadata records the feature
order, the category vocabularies, the reference year used for building age, the conformal offset
and a fingerprint of the training set, which is what lets a stored valuation be traced back to
the model and the data that produced it.

The artefact is committed. It is around 400 KB of text, and committing it means a fresh checkout
can value a listing without a database, a training run or a download.

### 6. The feature pipeline is shared, and the categorical vocabularies are pinned

One function builds the model matrix, and both training and the HTTP service call it. A feature
computed one way during training and another way at request time is the classic silent failure of
a deployed model.

LightGBM encodes a categorical as an integer code, so the order of a vocabulary is part of the
model contract: appending a value is safe, reordering one silently changes what every stored model
means. The Python lists are therefore checked against the TypeScript enums by a test.

## Consequences

- **LightGBM's categorical defaults had to be overridden.** `min_data_per_group` defaults to 100,
  which on a dataset with a few dozen listings per district blocks every categorical split. Left
  alone, the model refused to split on district or building type at all and fitted noise in the
  continuous columns instead; correcting it cut in-district error by more than half and moved
  district to the top of the importance table, where the data says it belongs. This is recorded
  because the failure was silent: nothing errored, the model simply learned the wrong thing.
- **The published metrics measure the pipeline, not the Yerevan market.** The data is synthetic
  with a known generative process and a known noise floor. The evaluation chapter says so in its
  own words, and the thesis must not present these figures as market evidence.
- **The model must not be pointed at a city it has no data for.** Almost everything it knows about
  price level is attached to the district. Extending to Gyumri or Vanadzor means collecting
  listings there.
- **The service never reads the database.** Training does, through an optional dependency, so the
  runtime image carries no driver and no connection string.
- A retrained model changes `modelVersion`, and every valuation stored against the old one keeps
  citing it. Recomputation is a migration, not a side effect.
